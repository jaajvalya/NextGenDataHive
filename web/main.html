      Apache Iceberg overview
      
      
      
        
      Apache Iceberg is an open table format for huge analytic datasets. It adds ACID transactions, time travel, schema evolution, and partition evolution on top of Parquet files stored in object storage (MinIO in the playground).
      
        
      In the playground, Iceberg tables live at s3a://iceberg-warehouse/<namespace>/<table>/ and are catalogued by Project Nessie.
      

        
      Iceberg table layout in MinIO
      
        
      iceberg-warehouse/
  datahive/
    products/
      metadata/
        v1.metadata.json         ← current table metadata
        snap-123.avro            ← snapshot manifest list
      data/
        part-00000.parquet       ← data files (Snappy compressed)
    orders/
      metadata/  ...
      data/
        order_status=completed/  ← partition directory
          part-00000.parquet
      

        
      Spark configuration for Iceberg + Nessie
      
        
      spark.sql.extensions = org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions
spark.sql.catalog.nessie = org.apache.iceberg.spark.SparkCatalog
spark.sql.catalog.nessie.catalog-impl = org.apache.iceberg.nessie.NessieCatalog
spark.sql.catalog.nessie.uri = http://nessie:19120/api/v2   # inside Docker
spark.sql.catalog.nessie.warehouse = s3a://iceberg-warehouse/
spark.sql.catalog.nessie.io-impl = org.apache.iceberg.aws.s3.S3FileIO
spark.sql.catalog.nessie.s3.endpoint = http://minio:9000
spark.sql.catalog.nessie.s3.path-style-access = true
      
      
      
    
      

    
      
      
      Iceberg features in the playground
      
      
      
        
      Time travel — read a previous version of a table
      
        
      -- By snapshot ID
SELECT * FROM nessie.datahive.orders VERSION AS OF 1234567890;

-- By timestamp
SELECT * FROM nessie.datahive.orders
TIMESTAMP AS OF '2026-08-01 00:00:00';

-- View all snapshots
SELECT snapshot_id, committed_at, operation
FROM nessie.datahive.orders.snapshots;
      

        
      Schema evolution — no data rewrite
      
        
      -- Add columns (existing rows return NULL)
ALTER TABLE nessie.datahive.orders ADD COLUMNS (
    discount_code STRING,
    is_gift BOOLEAN
);

-- Rename a column
ALTER TABLE nessie.datahive.orders RENAME COLUMN unit_price TO price;

-- Drop a column
ALTER TABLE nessie.datahive.orders DROP COLUMN is_flagged;
      

        
      Partition evolution
      
        
      -- Change partitioning without rewriting existing data
ALTER TABLE nessie.datahive.orders
REPLACE PARTITION FIELD order_status WITH days(order_date);
      

        
      Table maintenance
      
        
      -- Compact small files into larger ones
CALL nessie.system.rewrite_data_files(table => 'datahive.orders');

-- Remove orphan files left by failed jobs
CALL nessie.system.remove_orphan_files(table => 'datahive.orders');

-- Expire old snapshots
CALL nessie.system.expire_snapshots(
    table => 'datahive.orders',
    older_than => TIMESTAMP '2026-08-01',
    retain_last => 3
);
      
      
      
    
      

    
      
      
      
        
      Project Nessie — Git for data
      
        Catalog
      
      
      
      
        
      Nessie gives you Git-like branch and tag semantics for Iceberg tables. Create an experimental branch, write tables there, and the main branch is completely unaffected until you merge.
      
        
      Branch workflow in Spark SQL
      
        
      -- Create a feature branch
CREATE BRANCH dev IN nessie;

-- Switch to the branch
USE REFERENCE dev IN nessie;

-- Write a table (only visible on dev, not main)
CREATE TABLE nessie.datahive.experiment (...) USING iceberg;
INSERT INTO nessie.datahive.experiment VALUES (...);

-- Switch back — experiment table is absent on main
USE REFERENCE main IN nessie;
SHOW TABLES IN nessie.datahive;  -- experiment not listed

-- Merge dev into main when ready
CALL nessie.system.merge('dev', 'main');

-- Create an immutable tag (snapshot for auditing)
CREATE TAG v1.0 IN nessie AS OF main;

      Known quirks
      
      
      
        
      Spark JAR downloads on first submit. The spark.jars.packages setting in spark-defaults.conf triggers Maven downloads on the first job submission (~300 MB). Subsequent runs use the local cache.
      
        
      Glue image size. public.ecr.aws/glue/aws-glue-libs:glue4_image_01 is approximately 8 GB. Ensure Docker Desktop has at least 20 GB disk space allocated.
      
        
      MinIO vs LocalStack S3. The playground intentionally uses MinIO for object storage instead of LocalStack S3. MinIO has full S3A filesystem support required by the Hadoop connector for Iceberg writes. LocalStack S3 is only used for Lambda deployment packages.
      
        
      Nessie catalog inside Docker. Spark and Glue containers connect to Nessie at http://nessie:19120 (Docker hostname). When running spark-submit from the host machine, override to http://localhost:19120.
